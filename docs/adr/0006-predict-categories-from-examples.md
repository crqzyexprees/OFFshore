# 6. Predict Categories from labelled examples, not a trained classifier

Categories are predicted by matching each Transaction's description against labelled examples with a small, pre-trained sentence-embedding model (all-MiniLM-L6-v2, int8 ONNX, 23 MB, fetched at a pinned revision), rather than by the DistilBERT classifier trained in `ml/`. The available training data doesn't look like real Statements: one dataset has synthetic merchant names and the other has none, so a model trained on it scores well on its own test split and poorly on real descriptions, and every improvement needs a retraining run. Matching against examples needs no training, works from day one with a built-in starter set, and gets better with every correction, because the user's own corrections become examples (counted above the starter set) and correcting one Transaction re-predicts the others. The cost is an extra download at build time and predictions that are only as good as the nearest example; the trained-classifier path is kept as a fallback adapter behind the same interface. An online LLM was rejected as the default because it would send Transaction descriptions off the device.
